## Inspiration

**Keep the code. Calm the blink.**

A teacher has the finished recording, but the editable project is gone. In a real Jupyter tutorial, the code is already written while an empty-cell caret keeps blinking through the explanation. A whole-frame filter changes the lesson too. We wanted a smaller, testable promise: change only the observed detail the editor reviews, and check the downloaded teaching pixels and prepared narration.

Frame Review now takes **six untouched lesson originals** through upload, preparation, reviewed approval and checked export. Their distractions already occur in the recordings. No flashing corner was added to these cases.

## What it does

## How we built it

OpenCV 5 performs connected-component localization, source-state overlays, encoded RGB crops, error histograms and teaching-region measurements. A separate two-state luma proposal checks small stationary support, repeated transitions, bounded state/dwell errors and chroma stability. NumPy represents native YUV samples; FFmpeg performs bounded preparation, encoding and audio transport.

Approval binds the source, both analyses, implementation, exact proposal and teaching rectangles. The worker recomputes the proposal and measures the encoded result before accepting an edited download. The older rapid-change detector and periodic retimer remain frozen.

AWS runs the actual media workflow: managed HTTPS to owned upload, preparation, OpenCV review, approved FFmpeg export and checked downloads. The completed ECS/Fargate rollout uses a digest-pinned ECR image, CloudWatch logs, one bounded worker and an unprivileged process without application AWS API permissions. The deployment identity matches all 103 runtime files. All thirteen Linux qualification stages pass, including 137 backend tests and 78 studio tests (one platform skip), three natural preset exports, silent WebM transport and media/refusal integrations.

Codex assisted implementation, experiments, debugging and presentation. It is development assistance; no autonomous-agent award capability is claimed.

## Challenges and what failed

The earlier rapid retimer produced zero qualified natural repairs in a six-source/fourteen-excerpt audit. A Blender proposal was instructional content and was refused when protected; separate camera-lamp retimes failed recurrence. Those results remain published.

Compressed, low-contrast browser carets failed the older stationary rule. Proposal v2 admits bounded two-state variation while keeping exact encoded preservation. A maximum 60-frame dwell also prevents holding a caret through a long stopped or moved tail. The citations source now uses a supported four-second interval rather than the rejected full interval.

A real silent VP8 Cangjie recording exposed incorrect prepared chroma location. Preparation now converts and verifies left-sited chroma. The same original reaches review without a supported repair proposal, then returns its exact source and no-edit decision. A browser test also caught a Jupyter result linking to terminal credits; downloaded provenance now follows and matches the selected lesson.

## What the evidence covers

The new timing grid was declared before outcomes: four tutorial sources, three twelve-second excerpts each, at quarter/half/three-quarter duration. Three excerpts proposed repairs and all three original-upload cases qualified. All nine other outcomes are retained. Two earlier sources are development repairs; Tamil repeats the previous source. Presets and local/cloud reruns do not add independent sources.

Final code was revised after outcome inspection using development cases. This is a convenience development cohort without exhaustive distraction annotations, not held-out validation or a representative recall/success estimate. No creator time saving, attention, comprehension, adoption or user preference has been measured.

Preparation changes picture and sound: a supported 1–12 second excerpt is resized/letterboxed to 640x360/30fps, with optional mono AAC prepared once. It can erase teaching detail. Exact edit checks reference that prepared clip; the untouched upload remains separate. Intake is capped at64MiB. Fixed rectangles do not track objects, and there is no full-lesson splice-back. Jobs are ephemeral and known multimedia package findings remain.
